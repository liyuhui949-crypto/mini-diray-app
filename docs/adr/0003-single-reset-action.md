# ADR 0003：合并「重置日记」与「删除日记」为单一的「清空全部日记」

- 状态：已采纳
- 日期：2026-11-06
- 决策者：项目所有者
- 关联：`implementation-pipeline-v2.md` 需求矩阵 F6 / P8

## 背景

设置里原本有两个高危操作，效果高度重叠：

| 操作 | 行为 |
|---|---|
| 重置日记 | 清空全部条目与附件，保留密码与目录，回到三栏界面 |
| 删除日记 | 删除整个日记目录并回到引导页，需要重新建库 |

两者都需要密码 + 确认短语，都标注「不可恢复」。对单用户本地日记而言，多一个「把库删掉」的分支只增加误操作面，
产品负责人确认只保留一个。

## 决策

保留「**清空全部日记**」（原重置能力），删除「删除日记」：

- 清空所有条目、所有 `attachments/*.mdat`；
- 保留 `diary.vault`（因此密码、vaultId、目录都不变），应用停留在三栏界面，可以马上继续写；
- 依旧要求：密码校验 + 输入确认短语「清空日记」+ 执行前创建临时回滚点（成功后删除）；
- 移除 `vault:delete` IPC、`VaultRepository.deleteVault`、设置页「删除日记」入口与 `DeleteVaultDialog`；
- 想彻底删掉数据库的人可以直接删除设置页展示的日记目录（文件系统层操作，不需要应用提供入口）。

## 兼容性

- 迁移包、加密格式、`vault:reset` 的返回结构都没变；已导出/已导入的包不受影响。
- 唯一的外部契约变化是少了 `vault:delete` 这个 IPC 通道，仅有本仓库的渲染进程会调用它，已同步删除。

## 后果

- 危险操作区只剩一条，误触后也不会把应用打回引导页。
- 不再提供「应用内彻底删除库」的能力；这是有意取舍，文档里说明可以直接删目录。
