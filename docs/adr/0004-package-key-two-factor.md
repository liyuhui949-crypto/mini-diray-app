# ADR 0004：迁移包改用「公钥 + 私钥」双因子解锁

- 状态：已采纳
- 日期：2026-11-06
- 决策者：项目所有者
- 关联：`implementation-pipeline-v2.md` 第 8 章（一键迁移）、需求 F9 / F10

## 背景

原方案的迁移包只靠一个用户密码保护：包被拿走以后，攻击者可以离线无限次尝试密码（scrypt 只是拖慢速度，
不改变"可以一直试"这件事）。用户希望降低"导入密钥被暴力破解"的风险。

## 决策

导出时把解锁材料拆成两份：

| 角色 | 是什么 | 谁保存 | 是否在包里 |
|---|---|---|---|
| **公钥** | 应用生成的 **128 位**高熵字符串（56 符号字母表：大小写字母 + 数字，去掉 0/1/I/O/i/l/o，约 743 bit，`XXXX-XXXX-…` 分组展示） | 用户自己复制保存 | **不在**（包里没有任何痕迹） |
| **私钥** | 用户自定义的密码（≥ 8 位） | 用户自己记住 | **不在** |

- 真正参与 KDF 的是 `composePackageSecret(公钥, 私钥)`，两段任一错误都会得到完全不同的派生结果；
- `vault.inkv` 是标准的 vault 信封，只是 `keyWrap` 用的口令变成了这个组合串——加密格式本身没有改；
- 因此包被单独拿走时，攻击者必须先猜出 743 bit 的公钥（不可能），密码再弱也无法被离线爆破；
- 导入时必须同时提供公钥与私钥，错误统一提示「公钥或私钥不正确」，不暴露是哪一半错了。

## 界面规则

- 导出分两步：填私钥（可显示/隐藏）→ 生成公钥；
- 公钥只展示一次，带「复制公钥」按钮，并明确提示：应用不保存、丢失即包作废、不要和包放在一起；
- 生成公钥后强制 5 秒冷静期（按钮倒计时）才能开始导出，留给用户"抄下来"的时间；
- 导入时始终要求公钥，公钥支持带或不带短横线，但**区分大小写**（`A` 与 `a` 不同）。

## 兼容性

- 只支持 `packageFormat = 2`；更早的 `packageFormat = 1`（只靠密码、无需公钥）已不再支持，导入时会提示"来自旧版本"；
- 包内其余结构（`manifest.json`、`prefs.json`、附件密文、`checksums.sha256`）不变；
- IPC 变化：`migration:export` 增加 `packageKey`，`migration:preview` 增加可选 `packageKey`，
  新增 `migration:inspect`（只读清单判断是否需要公钥）与 `app:copyText`（写剪贴板，避免依赖浏览器权限）。

## 权衡

- **公钥丢失 = 包永久打不开**，比原来更容易"人祸"；用强提示 + 复制按钮 + 5 秒冷静期来对冲；
- 公钥与包必须分开存放，否则退化成单因子；文案里明确写了这一点；
- 公钥约 743 bit，无法暴力枚举，安全性由它兜底，私钥只需满足密码习惯即可；
- 128 位字符串很长，只能靠复制粘贴，界面因此提供一键复制，并在导出时强制 5 秒冷静期提醒先保存。
