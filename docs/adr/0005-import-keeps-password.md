# ADR 0005：导入迁移包不再要求设置新密码

- 状态：已采纳
- 日期：2026-11-06
- 决策者：项目所有者
- 关联：`implementation-pipeline-v2.md` 第 8.4 节（导入流程）、需求 F9 / F11

## 背景

原来的导入流程在预览之后要求用户「设置新密码 + 确认」，理由是用新密码重新包裹目标 DEK。
实际使用中这一步是多余的：绝大多数情况下用户要么在替换自己的库（密码没变），
要么在全新安装时导入（刚刚已经输过迁移包的私钥）。

## 决策

导入不再询问新密码，按场景决定导入后的解锁密码：

| 场景 | 导入后解锁密码 | 密钥处理 |
|---|---|---|
| 合并到当前已解锁的库 | **当前日记密码不变** | 保留目标 vault 的 keyWrap，只重新加密 payload |
| 替换当前已解锁的库 | **当前日记密码不变** | 同上（附件目录整体换成包内的） |
| 没有库（全新安装） | **迁移包的私钥（包密码）** | 采用包内 DEK，用包密码重新包裹 |
| 库被锁定 + 替换 | **迁移包的私钥（包密码）** | 同上（锁定时拿不到目标 DEK） |

- 界面在模式步骤直接说明「导入后继续用当前的日记密码解锁」或「用迁移包的私钥解锁」；
- `migration:import` IPC 去掉 `newPassword` 字段；
- 已解锁的场景不再调用 `rewrapEnvelope`（少一次 scrypt，也避免"改了密码自己不知道"）。

## 实现要点

- 已解锁的库走**原地替换**：先备份很小的 `diary.vault` 到 `migration/rollback-<jobId>/`，
  再把 staging 附件搬进（replace 时旧附件目录整体 rename 到回滚点），
  最后用 `repository.replaceAllWithCurrentKey(nextData)` 原子写入新 payload（keyWrap 不变）；
- 失败回滚：撤掉搬进来的附件、恢复旧附件目录、把旧数据写回 vault；
- 没有库/库被锁定时仍走 staging + 整体切换（`switchStagingIntoPlace`），
  新 vault 用包密码包裹，切换后立即用包密码解锁验证。

## 兼容性

- 迁移包格式不变（`packageFormat = 2` 仍需公钥 + 私钥才能打开包）；
- 已导出的包不受影响；导入后库的解锁密码规则见上表，文档与界面都写清楚；
- `migration:import` 的返回结构不变，仅少了一个入参。

## 后果

- 少一步输入，导入路径更短；忘记密码的风险从"新密码"变成"当前密码/包密码"，两者用户本来就知道。
- 全新安装导入后，库的解锁密码就是迁移包的私钥；用户如果希望换密码，可以之后在设置里改。
