# Git 同步

Git 同步是可选功能，默认关闭。它只同步加密后的正文和批注，不同步附件，也不同步今天的内容。

## 同步范围

会进入仓库：

```text
.sync/
├─ sync.json
├─ entries/<日期>.ink
└─ annotations/<日期>.ann
```

不会进入仓库：

- 今天的正文和批注；
- 附件 `.mdat`；
- 密码、DEK；
- Git token；
- 代理设置；
- 应用偏好和日志。

`.ink` 是加密后的完整条目，包含标题、正文、标签、附件元数据和时间戳；附件文件本身不进入 Git。

## 仓库与镜像

本地镜像位于：

```text
<日记目录>/.sync
```

它只是从日记库派生出来的 Git 缓存，不是源数据。

`sync.json` 记录 `vaultId`。一个 Git 仓库只能对应一个日记库；旧库留下的镜像会在同步前被丢弃。

## 推送流程

1. 检查同步开关和当前密码；
2. 从 vault 生成 `.sync` 镜像，只写今天以前的条目；
3. 提交真正变化的文件；
4. `fetch` 远端；
5. 如果远端有本地没有的提交，提示先拉取；
6. 正常 `push` 到配置的分支。

应用不会自动 force push。远端历史与本地无关时，需要先拉取或手动处理。

## 拉取流程

1. 生成本地镜像快照；
2. `fetch` 远端；
3. 本地领先：不合并；
4. 本地落后：fast-forward；
5. 两边分叉：把本地镜像重置到远端；
6. 读取远端镜像，合并回 vault：
   - 条目按日期合并，同一天取 `updatedAt` 较新的一方；
   - 批注按内容去重；
   - 今天的条目永远不动；
7. 下次推送时从合并后的 vault 重新生成镜像。

本地未推送的正文在拉取分叉恢复时仍保留在 vault 中，不会被镜像重置删掉。

## 认证与网络

- 使用系统 `git`，不内置 Git；
- 只支持 `https://` 仓库；
- token 使用 `x-access-token` 作为 Basic 用户名；
- Fine-grained token 需要 Contents: Read and write；
- 代理只影响同步子进程。

token 用日记库密钥派生的 `sync-token-v1` 密钥加密保存，不写偏好、不进日志、不进迁移包。

## 恢复密钥

清空本地库或换电脑后，Git 仓库里的密文需要原来的 DEK 才能解开。

可以导出 `.inkkey`：

- 包含备份密码包裹的 DEK；
- 加密携带仓库地址和分支；
- 不包含 token、代理、正文、附件。

恢复时会创建同一个 `vaultId` 的空库，填入仓库地址和分支；token 仍需手动填写，然后拉取。

没有 `.inkkey` 或 `.minidiary`，只靠 Git 仓库无法解密。

## 限制

- 默认关闭；关闭时不运行 Git、不联网；
- 今天的内容不进入同步，第二天才可能被推送；
- 附件永远不进入 Git，使用 `.inkatt` 单独迁移；
- 没有单条删除同步，也没有 tombstones；
- 不支持 SSH；
- 不做 Git 文件级自动合并；
- 应用内没有 force push；
- Git 历史是版本记录，但应用没有“回滚到某天”的按钮。
