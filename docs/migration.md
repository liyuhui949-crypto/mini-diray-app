# 一键迁移

一键迁移用一个 `.minidiary` 文件搬走整个日记库：正文、批注、附件、加密密钥和部分设置都在里面。

## 适用场景

- 换电脑；
- 重装系统前做完整备份；
- 归档某个时间点的完整日记库；
- 把库合并到另一台设备。

## 包内有什么

`.minidiary` 是 ZIP64 容器：

```text
manifest.json           # 格式、版本、条目/附件数量、时间
vault.inkv              # 重包后的日记库信封
prefs.json              # 可移植设置
annotations/<日期>.ann  # 批注密文
attachments/<id>.mdat   # 附件密文
checksums.sha256        # 成员校验和
```

包内没有明文正文，也没有明文附件。

## 两个密码

导出时需要设置：

- **公钥**：应用生成的一次性 128 位随机字符串，只显示一次；
- **私钥**：自定义的包密码。

两者共同参与 DEK 的包裹。导入时缺少任何一个都无法打开。

> 公钥和私钥请分开保存。放在一起等于没有这层保护。

## 导出流程

入口：

```text
同步 → 数据 → 一键迁移 → 导出…
```

1. 输入私钥，并再次确认；
2. 应用生成公钥；
3. 复制并保存公钥；
4. 等待冷静期结束；
5. 选择保存位置。

导出时：

- 先 flush 当前日记库；
- 用现有 DEK 重新包裹迁移包密钥；
- 附件密文原样复制，不解密、不重新压缩；
- 写入临时 `.part`，校验完成后原子改名；
- 失败会删除临时文件。

如果正文引用了本地不存在的附件，导出会失败，而不是生成一个不完整的包。

## 导入流程

首次安装、没有本地库时：

1. 选择「导入迁移包」；
2. 选择 `.minidiary`；
3. 输入公钥和私钥；
4. 预览条目数、附件数和日期范围；
5. 选择整库替换。

导入到**没有库**的环境时：

- 采用包内的 `vaultId` 和 DEK；
- 之后用迁移包私钥作为日记库密码；
- 不需要另外设置新密码。

如果导入到**已解锁的现有库**，则保留目标库的密钥和密码，只把内容合并进来。

### 替换与合并

- **替换**：用包内内容替换当前内容；保留目标库的密钥（如果已有库）。
- **合并**：同一天的内容合并，包内附件会分配新 ID，正文里的附件引用同步改写。

导入过程先写 staging，校验通过后才原子切换；失败会回滚，不会留下半导入状态。

## 会携带哪些设置

迁移包会携带：

- 主题、隐藏标题、未来日期、自动锁定；
- Git 同步的开启状态、仓库地址、分支。

不会携带：

- Git token；
- Git 代理；
- 本机路径、日志。

导入后如果开启了 Git 同步，仍需重新填写 token。

## 限制

- 公钥或私钥丢失后，包无法打开；
- 旧版不需要公钥的迁移包已不再支持导入；
- 迁移包是完整备份，但应用不做自动备份；
- 包内附件会全部带走，包括没有被正文引用的孤儿附件；
- 合并导入不会删除目标库已有条目。
