# Git 同步

Git 同步只搬**正文与批注**，不搬附件；今天的内容永远不同步。附件用 `.inkatt` 附件包手动迁移。

**默认关闭。** 关闭时不会运行任何 `git` 命令，也不会让应用发起 HTTP(S)；仓库地址、密钥、代理仍保留，重新开启即可继续。

## 1. 范围与决议

| 数据 | 是否进 Git | 说明 |
|---|---|---|
| 正文 `entries/<date>.ink` | ✅ | 只提交今天以前的日期 |
| 批注 `annotations/<date>.ann` | ✅ | 只提交今天以前的日期 |
| 附件 `.mdat` | ❌ | 用「数据 → 仅迁移附件」导入/导出 `.inkatt` |
| 今日正文/批注 | ❌ | 当天不提交、不拉取；第二天自动补上 |
| 偏好/日志/密钥 | ❌ | 本机数据，不进仓库 |

- **不内置 git**：调用用户环境里的系统 `git`，不打包 Git、不打包 isomorphic-git。
- **只提交变化（M）**：镜像里内容没变的条目不会重写；git 只看到真正改过的文件。
- **不做删除同步**：产品不提供删除单篇日记/附件的入口；今日被清空的内容本来就不在镜像里。
- **不做 Git 自动合并**：能快进就快进；分叉时拉取以远端镜像为基准重建本地镜像（正文仍在 vault），再按更新时间/批注内容合并，最后重新推送。
- **总开关**：默认关闭；关闭态不运行 git、不联网，`.sync` 仅保留为惰性本地缓存；开启后才允许测试/拉取/推送。
- **本地网络权限**：关闭时应用不会发起任何本地网络访问；只有开启同步并实际通过本地代理连接时，macOS 才会请求本地网络权限。「设置 → 关于 → 需要的权限」提供「打开本地网络设置」，直接跳转「系统设置 → 隐私与安全性 → 本地网络」。授权记录由 macOS 保存，关闭同步不会自动撤销，需要在该页面手动关闭。

## 2. 仓库与本地镜像

### 2.1 远端布局

```
<repo>/
├─ sync.json                 # { format: 1, vaultId }
├─ entries/
│  └─ 2026-11-08.ink        # 每条日记一个密文文件
└─ annotations/
   └─ 2026-11-08.ann        # 每天的批注密文（原样复制）
```

- `sync.json` 用来校验仓库属于哪个 `vaultId`；不一致会拒绝同步。
- 每个 `.ink` 是 `AES-256-GCM` 密文，密钥为 `HKDF(DEK, vaultId, "sync-v1")`，AAD 绑定 `vaultId + date`。
- 文件里不出现标题/正文/标签明文；但**文件名会泄漏哪些天有日记/批注**，文件大小会泄漏大致篇幅。

### 2.2 本地镜像

镜像位于日记目录下的 `.sync/`：

```
<日记目录>/
├─ diary.vault               # 原来的单文件库，保持不动
├─ attachments/              # 附件，不进 git
├─ annotations/              # 本地批注
└─ .sync/                    # git 仓库（镜像）
   ├─ .git/
   ├─ sync.json
   ├─ entries/
   └─ annotations/
```

- 本地库仍是单文件 `diary.vault`，**不需要改存储格式**；
- 推送前从 vault 生成/更新镜像，拉取后把镜像解密合并回 vault；
- 清空全部数据会删除本机日记库、附件、密码、偏好、令牌和 `.sync`，回到首次安装状态；远端仓库不受影响。更改日记目录会移除 `.sync` 并断开同步。

## 3. 今日规则

- 推送时，`date >= 今天` 的条目与批注不写入镜像；镜像里若残留今天的文件会被移除；
- 拉取时，远端今天/未来的条目与批注也会被忽略；
- 因此**当天写的日记不会出现在另一台设备上**；第二天再推送时才会补上；
- 今天的清空/改写也不会产生任何远端删除。

## 4. 推送流程

1. 检查本机 `git`（找不到时提示安装 Git）；
2. 从 vault + 本地批注生成 `.sync` 镜像（只重写内容有变化的文件）；
3. `git add -A`；
4. 没有变化 → 不产生 commit；有变化 → `commit`；
5. `git push -u origin HEAD:<branch>`；
6. 失败时本地 commit 保留，下次可直接重试；状态栏记录失败原因。

## 5. 拉取流程

1. 先构建一次镜像，检查工作区是否干净；有未推送改动时要求先推送（避免覆盖本地）；
2. `git fetch origin`；
3. 本地领先则无需拉取；落后则 `git merge --ff-only origin/<branch>`；分叉则 `git reset --hard origin/<branch>`，因为 `.sync` 只是派生缓存，正文仍以 vault 为准；
4. 解密 `entries/*.ink` 与 `annotations/*.ann`（只取今天以前）；
5. 条目按日期合并：同一日期取 `updatedAt` 较新的一方；
6. 批注按内容去重；id 冲突时重新编号，并重写本地 `.ann`；
7. 刷新附件缺失状态。

## 6. 附件：`.inkatt` 包

附件不进入 Git。设备间搬运走「数据 → 仅迁移附件」：

```
minidiary-attachments.inkatt      # ZIP64
├─ key.enc                        # 公钥+私钥包裹的 DEK（scrypt + AES-GCM，不含 payload）
├─ manifest.enc                   # 用 DEK 派生的 manifest 密钥加密的清单
├─ attachments/<uuid>.mdat        # 原样复制的密文
└─ checksums.sha256               # 每个成员的 SHA-256（最后一个成员）
```

- 导出必须设置**私钥**（包密码）并保存应用生成的**公钥**；两者同时正确才能解开 `key.enc`；
- `manifest.enc` 用解锁出的 DEK 派生密钥加密，包内看不到附件元数据；
- 导入先校验 `key.enc`/`manifest.enc` 的校验和，再解 `key.enc`、解 `manifest.enc`，最后逐项校验 `vaultId`、MDAT 头与大小；
- 附件包只补齐**同一个 vault**（DEK 一致）的附件；新设备先导入 `.minidiary`，不同库的附件包会被拒绝；
- 已存在且哈希一致则跳过，不一致直接报错；只补缺失文件，不覆盖；
- 导入完成后，正文里的占位卡自动恢复为正常媒体卡。

## 7. 缺失附件状态

文本先同步、附件还没导入时，正文会引用本机不存在的 `.mdat`。界面按三处联动：

| 位置 | 展示 |
|---|---|
| 正文附件区 / 预览 | 琥珀色虚线占位卡：文件名、大小、「附件尚未迁移」、`去迁移 →` |
| 日记列表 | `缺 n 附件` 角标 |
| 编辑器状态栏 | `n 个附件（m 个未迁移）` |

- 打开侧栏「同步」的数据页 → 导入 `.inkatt` → 占位卡消失；
- 缺失只表示“本机没有文件”，不猜测原因，也不自动删除元数据；
- 导出/迁移时缺失附件会跳过，不会生成假的明文文件。

## 8. 配置

### 8.1 前置

- 系统已安装 `git`（macOS 自带或 Homebrew；Windows 安装 Git for Windows；Linux 用发行版包）；
- GitHub 私有仓库（空仓库也可以，第一次推送会创建分支）；
- 一个 GitHub Personal Access Token（fine-grained 至少给目标仓库 Contents: **Read and write**，或 classic `repo`）。
  不需要填写用户名：应用固定用 `x-access-token` 作为 Basic 用户名，真正身份由 token 决定。

### 8.2 同步面板

侧栏「同步」在右侧主区域打开面板（与设置同一布局），两个页签（默认打开数据页）：

- **数据**（默认）：日记目录、一键迁移（`.minidiary`）、仅迁移附件（`.inkatt`）、清空全部数据；
- **Git 同步**：总开关（默认关闭）/ 状态 / 拉取 / 推送 / 仓库地址 / 令牌 / 代理 / 打开同步文件夹；关闭时这些选项全部隐藏，也不会启动 git。

令牌用日记库 DEK 派生的密钥加密保存（锁定后不可读），不写偏好、不写日志、不进迁移包，也不再需要系统钥匙串权限。
代理走 `git -c http.proxy=…`，不依赖系统 git 配置；**不支持 SSH**，仓库地址必须是 `https://`。

### 8.3 新设备

Git 仓库只有条目/批注密文，没有 DEK 信封。新设备必须先有**同一把 vault**：

1. 用「数据 → 一键迁移」导入 `.minidiary`（或复制 `diary.vault` + `annotations/`）；
2. 再配置同一个仓库并拉取。

不同密码/不同 `vaultId` 的库不能直接拉取；`sync.json` 会拒绝，防止把两套密文混在一起。

## 9. 错误与限制

| 情况 | 行为 |
|---|---|
| 同步未开启 | 测试/拉取/推送直接拒绝（`SYNC_DISABLED`），不运行 git、不联网 |
| 找不到 git | 同步面板提示安装；不打包 git |
| 令牌失效 / 无权限 | 401：`令牌无效或已过期`；403 / `Write access to repository not granted`：令牌没有写权限（Fine-grained 需 Contents: Read and write、选中仓库、组织需 SSO）；本地内容不丢 |
| 代理不通 / DNS 失败 | 分类提示；代理仅应用内配置生效 |
| 远端非 fast-forward | 推送提示先拉取；拉取以远端镜像重建本地镜像，本地未推送内容仍保留在 vault，再推送即可 |
| 今天的内容 | 不会出现在仓库，也不会被拉取 |
| 删除单篇 | 产品不提供；镜像也不会替远端删除 |
| 冲突（两端改同一天） | 不做 Git 文件合并；拉取后按 `updatedAt` 保留较新正文，批注按内容去重 |
